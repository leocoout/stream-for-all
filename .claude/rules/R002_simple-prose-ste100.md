# R002 — User-facing prose follows ASD-STE100 principles

**Rule:** All user-facing prose in this project follows the principles of ASD-STE100 (Simplified Technical English), adapted to the target language of the text.

## Scope

- Privacy policy, store listing texts, README sections aimed at users, landing page copy, in-app strings when they are full sentences.
- Does not apply to code identifiers or short UI labels.

## Requirements

- Write short sentences. Maximum 20 words for instructions, 25 for descriptions.
- Use active voice. Name the actor: "A extensão guarda o apelido", not "O apelido é guardado".
- One idea per sentence. One topic per paragraph.
- Use present tense where possible.
- Use the same word for the same thing everywhere. Do not vary terms for style.
- No em dashes (—) or spaced hyphens as punctuation. Use a period, comma, or colon instead.
- No aphorisms, slogans, or flourishes ("de verdade", "ninguém no meio", "em segundos").
- No idioms or figurative language. Say the literal fact.
- Prefer concrete words over abstractions. State what happens, not what it means.
- Lists: use a lead-in sentence, then parallel items. Start items the same way.

## Test

Read each sentence alone. If it states one verifiable fact or one instruction in plain words, it passes. If it decorates, persuades, or repeats, delete it.
